# 用宁好学会 the AI agent way

这份文档用宁好做例子，讲清楚一个 AI agent 是怎么搭起来的，以及以后你怎么用 Claude Code 自己继续改它。

## 1. Agent 到底是什么？

一句话：**能自己感知环境、做出判断、采取行动，并且会反复执行的程序。**

拆开看有五个部件，宁好每一个都有：

| 部件 | 作用 | 在宁好里 |
|---|---|---|
| 触发器 | 什么时候开始干活 | GitHub Actions 每 30 分钟触发一次 |
| 感知 | 从外部获取信息 | `fetch.py` 抓 RSS、Google 新闻、联邦公报 |
| 判断 | 理解信息，做决定 | `analyze.py` 让大模型（默认 Gemini，可换 Claude）以宁德时代视角写情报卡 |
| 记忆 | 记住做过什么 | `state.json` 记录看过的新闻，`feed.json` 存情报 |
| 行动 | 改变外部世界 | 更新网站、推送到群聊 |

传统程序也有触发器、感知、记忆和行动。**AI agent 的不同在于「判断」这一步交给了大模型。** 以前要写几百条规则才能判断一条新闻重不重要，现在写一份说明书（`lens.md`）就行。

## 2. Workflow 还是 Agent？先选最简单的

AI 应用按自主程度分三档：

1. **单次调用**：问一次，答一次。比如翻译一段话。
2. **Workflow（工作流）**：流程由代码固定，AI 只负责其中某几步的判断。**宁好现在就是这一档。**
3. **Agent（自主智能体）**：AI 自己决定下一步做什么、调用什么工具、什么时候停。

先从简单的做起。宁好的流程是固定的（抓取 → 补全 → 判断 → 存储 → 发布），用 workflow 最稳定、最便宜，也最容易排查问题。

什么时候需要升级成 agent？当任务变得开放、无法提前写死步骤时。比如：
- 「看到一条重大新闻，自己决定去搜更多相关报道，再写一份深度分析」
- 「被问到 FEOC 规则的变化时，自己翻历史情报、查原文、整理时间线」

这时可以给 Claude 配上工具（网页搜索、读取情报库），让它自己循环调用。

## 3. 最重要的一个文件：提示词就是岗位说明书

`config/lens.md` 决定了宁好的判断质量。写好它，可以参考写岗位说明书的思路：

- **你是谁**：宁德时代海外业务的情报分析师
- **读者是谁**：很忙、懂行业、没时间读英文原文的同事
- **关心什么**：六类变化，每类写清楚具体指什么
- **怎么打分**：给出影响分 1–5 的标准和例子
- **底线**：不编造、不猜测、不给股票建议

一个经验：**规则写不清楚的地方，就给例子。** 例子比形容词更能让模型理解你要什么。

## 4. 让 AI 的输出可以被程序使用：结构化输出

如果让模型自由写一段话，程序就很难排序、筛选、推送。

所以 `analyze.py` 定义了一个 JSON 表格（`SCHEMA`），要求模型必须按格式填写：分类只能从 6 个里选，影响分只能是 1–5，等等。Gemini 和 Claude 的 API 都有结构化输出功能，会保证返回的是合法 JSON。代码拿到结果后还会再检查一遍，不合格的丢掉、下次重试。

**原则：凡是程序要用的字段，都用结构化输出约束；只给人看的字段，才让 AI 自由发挥。**

**再进一步：让错误可以被核对。** 模型总会出错，一条条打补丁防不完。宁好的做法是要求每条要点附上原文原句，代码逐字检查这句话在不在原文里：编造的句子会被直接丢掉；就算模型把原句读错了（比如把「$1.6 billion」写成容量），读者对照原句也能马上发现。这比追求「模型永不出错」更现实。

## 5. 怎么知道 AI 判断得准不准：评估

改了 `lens.md`，结果到底变好还是变坏？凭感觉不可靠。正确做法是：

1. 挑 30 条有代表性的新闻，自己先标注：相关吗？影响几分？机会还是风险？
2. 每次改完提示词，用这 30 条跑一遍，对比 AI 和你的标注。
3. 记录准确率。只有分数提高了，才保留这次修改。

这叫 **eval（评估集）**。它是专业 AI 产品和玩具的分水岭，也是面试时很好的谈资。

## 6. 成本和速度

- **先用便宜的方法过滤**：关键词预筛能挡掉大部分无关新闻，它们不会占用模型额度。
- **只处理新内容**：`state.json` 记住看过的条目，避免重复分析。
- **设上限**：`max_new_per_run` 限制每次最多分析多少条。
- **模型可换**：默认用 Gemini 的免费额度；需要更高的判断质量时，设 `NINGHAO_PROVIDER=claude` 换成 Claude。用 Claude 时，`NINGHAO_EFFORT=low` 更快更便宜，`high` 更仔细。
- **怎么选模型**：用第 5 节的评估集，同一批新闻让两家模型各跑一遍，看哪家判断更准、每条成本多少，再决定。

## 7. 用 Claude Code 继续开发宁好

在宁好文件夹里打开 Claude Code，它会先读 `CLAUDE.md` 里的项目规则。之后可以直接用中文描述需求，比如：

- 「给宁好加一个信息源：Fluence 的 SEC 8-K 公告」
- 「把同一事件的多篇报道合并成一条，显示『3 家媒体报道』」
- 「做一个 30 条的评估集，测一下 lens.md 的准确率」
- 「页面加一个按地区筛选的下拉框」

好的工作习惯：

1. **复杂的需求先进 Plan Mode**：让 Claude 先出方案，你确认后再动手。
2. **一次只改一件事**：改完先验证（`--dry-run`、`--max 5`、打开网页看），再提交。
3. **每次改动都 git commit**：出问题可以随时回退。

## 8. 面试时怎么讲（3 分钟）

1. **痛点（30 秒）**：海外业务每天面对大量英文信息，真正影响决策的不到一成，而且需要「翻译」成对公司的含义。
2. **演示（90 秒）**：
   - 打开网站，展示头条和情报流
   - 点开一条，讲「原标题 → 我们的标题」的转换，以及原文要点和建议动作
   - 筛选「政策法规 + 风险」
   - 搜索「FEOC」
3. **设计思路（40 秒）**：信息价值 = 相关度 × 意外程度 × 时效；不编造是底线；视角文件化，方便业务人员维护。
4. **和岗位的关系（20 秒）**：产业资本投资专员要做行业研究和趋势研判。宁好就是把这份日常工作自动化、标准化的工具，也能用来发现投资标的和风险信号。
